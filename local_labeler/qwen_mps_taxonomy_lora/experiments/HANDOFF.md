# Handoff: серия экспериментов над LoRA-разметчиком (Qwen3-8B, MLX, Mac 32 ГБ)

Этот документ — единственное, что нужно прочитать, чтобы запустить эксперименты.
Логика и обоснование — в [`TIER0_PLAN.md`](./TIER0_PLAN.md) и [`TIER1_PLAN.md`](./TIER1_PLAN.md).

## TL;DR
Подготовлено всё, кроме 2 пунктов, которые надо сделать самой (см. «Что осталось пофиксить»).
Дальше каждый эксперимент запускается одной командой:
```bash
bash run_experiment.sh E0   # потом E1, E2, E3 ; затем (Tier 1) E4, E5
```
Команда сама: обучает → прогоняет инференс на замороженном тесте → считает метрики → дописывает строку в `experiments/results.csv`.

---

## Идея в двух абзацах
Текущая модель схлопывается в мажоритарный класс на 14 из 37 полей (честный mean per-field macro-F1 = **0.667**,
а не 0.813 — flat-метрика завышена). Эксперименты проверяют 3 гипотезы по одному фактору за прогон:
**lr (E1) → rank (E2) → данные (E3)**, а затем глубину адаптации **num_layers (E4, E5)**.

Главное правило: **меняем по одному фактору**, чтобы можно было атрибутировать эффект. Поэтому есть контрольный
прогон E0 и греди-цепочка: каждый следующий эксперимент строится на победителе предыдущего.

## Что осталось пофиксить (только это!)

**1. Зафиксировать датасет (preflight).** Сейчас рассинхрон: `manifest.json` говорит n_train=6767,

Перегенерировать и заморозить:

```bash
# проверь manifest.json: n_train должно стать 6767
```

> (это 2 эпохи для 5544). Конфиги сейчас рассчитаны на 6767.

**2. Прогнать дымовой тест lr_schedule (1 минута).** Схема cosine проверена для mlx_lm 0.31.3
(`{name, arguments:[init, decay_steps, end], warmup}`), но на всякий случай убедись, что обучение
стартует без ошибки конфигурации:
```bash
source .venv/bin/activate
```

Больше ничего «фиксить» не нужно — пути, адаптеры, метрики и команды уже прописаны.

## Порядок запуска

### Tier 0 (бесплатные рычаги, ~3–4 ч на прогон)
```bash
bash run_experiment.sh E0    # контроль (можно пропустить, если доверяешь старому metrics.json)
bash run_experiment.sh E1    # + lr 1e-4 + cosine
bash run_experiment.sh E2    # + rank 32   (строить на победителе E1; если E1 не помог — оставить rank 8)
# Перед E3: сгенерировать балансированные данные
python scripts/oversample_train.py --in-dir ./data_mlx --out-dir ./data_mlx_balanced --inflate 1.5 --seed 42
bash run_experiment.sh E3    # + oversampling
```
`run_experiment.sh` оценивает **финальный** адаптер. Чтобы взять лучший чекпойнт (а не последний) —
после обучения запусти отбор по valid (он же посчитает финальное число на test, метка `E*-best`):
```bash
bash select_best_checkpoint.sh E1            # 3 последних чекпойнта + финал, оценка на valid -> лучший на test
bash select_best_checkpoint.sh E1 5 200      # вариант: 5 чекпойнтов, valid ускорить первыми 200 строками
```
После Tier 0 выбери **победителя T0\*** = максимум `mean_f1_all` при не-просевшем `mean_f1_good`
(сравнивай строки `E*-best`, если запускала отбор чекпойнтов).

### Tier 1 (глубина, дорого по времени; запускать ПОСЛЕ Tier 0)
Открой `configs/tier1_E4.yaml` и `tier1_E5.yaml` — они собраны в предположении, что T0\* = E2
(lr1e-4+cosine, rank32, без балансировки). **Если твой победитель другой** — скопируй его конфиг
и поменяй ровно одну строку `num_layers` (16 для E4, 24 для E5); при необходимости `data`/`iters`.
```bash
bash run_experiment.sh E4    # num_layers 16  (~5–6 ч)
bash run_experiment.sh E5    # num_layers 24  (~7–9 ч). При OOM см. шапку tier1_E5.yaml (rank↓, потом seq↓)
```

## Как читать результат
`run_experiment.sh` в конце печатает (и пишет в `experiments/results.csv`):
- **mean_f1_all** — главный критерий (база 0.667);
- **mean_f1_collapsed** — 14 проблемных полей (база ≈0.48), сюда целимся;
- **mean_f1_good** — guardrail (база ≈0.943), НЕ должен заметно падать (особенно после E3).

Правило отбора: изменение принимаем, если вырос `mean_f1_all` **и** `mean_f1_good` не обвалился (>~3 п.п.).
Иначе откатываемся, и следующий эксперимент строим на прошлой лучшей конфигурации.
`flat_macro_f1` для отбора не используем — он маскирует проблему.

Готовые таблицы для заполнения — в `TIER0_PLAN.md §8` и `TIER1_PLAN.md §8`.

## Совет по времени (Mac медленный на 8B)
Для отбора чекпойнта не гоняй инференс по всем 12 сохранённым адаптерам — это долго.
`select_best_checkpoint.sh` по умолчанию берёт только 3 последних + финальный и оценивает на valid;
третьим аргументом можно ограничить valid первыми K строками (напр. `... E1 3 200`), чтобы ускорить отбор.
Полный test считается один раз — для победителя.
